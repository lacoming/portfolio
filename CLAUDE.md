# Правила проекта

- После любой правки сайта в `sites/` обновляй его превью `previews/<key>.jpg` (924×520, JPEG, скрин верха страницы). Ключи: tokeon, rentsale-altay, flexpath, univer-zakupok, tersk, termy, bastard-world, gastro, atelier.
- Исключение: `previews/tokeon.jpg` — курированный скрин, поверх него анимируется отдельный слой `previews/tokeon-sphere.png`. Не перезаписывать без явной просьбы.
- `sites/last-signal/` и `previews/last-signal.jpg` временно сняты с витрины (сайт переделывается) — файлы не удалять.
- Переменные окружения Vercel: `DATABASE_URL` (Neon), `ADMIN_PASSWORD` и `ADMIN_SECRET` (админка), `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (уведомления о заявках). Без телеграм-переменных форма работает, заявка просто ложится в базу без уведомления. В репозиторий ничего из этого не класть — `.env` и `.env.*` в `.gitignore`.
- `sites/zen-garden/` — собранная статика мини-игры «Космический дзен-сад», руками не править. Исходники: `D:\cody\vizitka\portfolio (1)` (`src/modules/zen-game/`, `src/data/plants.ts`, `src/lib/zenLeaderboard.ts`, `src/lib/profanity.ts`). Пересборка: `vite build --config vite.config.zen.ts` из корня исходников, затем `dist-zen/assets/*` → `sites/zen-garden/assets/` (старые хешированные файлы удалить) и `dist-zen/zen.html` → `sites/zen-garden/index.html`. Файлы из `public/` (plants, icons, favicon) копировать только при их изменении, `plants old/` и `Слой 11.png` в витрину не тащить.
- Таблица лидеров игры — `api/zen-board.js` поверх той же базы Neon (`DATABASE_URL`), таблица `zen_players` создаётся лениво. Ник одновременно бронируется: уникальный индекс по нормализованному имени. Мат-фильтр `api/_profanity.js` продублирован на клиенте игры в `src/lib/profanity.ts` — правки нужны в обоих файлах. Прежний бэкенд на Supabase умер вместе с проектом, ключей от него нигде не осталось.
- Локальная проверка витрины вместе с `/api/zen-board`: `node .claude/serve-vitrina-api.js "D:\cody\Portfolio витрина сайтов" 4322` — статика плюс эндпоинт в памяти (настоящий мат-фильтр, база не нужна).
- `shots/<key>-N.jpg` — скриншоты внутри карточки кейса (блок «1С и автоматизация»), задаются полем `shots` в массиве `OTHERS`. Клик открывает снимок целиком, поэтому кадр кладём в исходном разрешении (до 1600 px по ширине, JPEG q≈86). Третий кадр в карточке рисуется во всю ширину — под него берём широкий снимок. Персональные данные на скринах из клиентских баз замазывать до попадания в репозиторий. `shots/parser-bets-1.jpg` и `shots/scanner-odds-1.jpg` — не снимки клиентских выгрузок, а макеты окна Excel с вымышленными данными (структура колонок повторяет реальные отчёты). Исходник макетов — `.claude/shots-src/xl_excel_mockups.py` (пишет HTML, снимок снимается playwright'ом). `shots/n8n-orchestrator-1.jpg` — настоящий канвас n8n: локальный одноразовый инстанс, в базу вставлены сценарии из `D:\cody\Freelance\n8n_Mini_Orchestrator\workflows`, съёмка — `.claude/shots-src/n8n_canvas_shot.py`.
- `sites/bastard-world/` — статическая копия главной bastard.world: боевой сайт запрещает встраивание в iframe (`X-Frame-Options: SAMEORIGIN`, CSP `frame-ancestors 'self'`). Пересобирается скриптом `sites/bastard-world/_src/snapshot.py` из корня витрины.
